# Architecture

## 进程边界

```text
React Renderer
  │  contextBridge（类型化最小 API）
  ▼
Electron Main
  ├─ AuthService：官方登录、Token 验证和加密持久化
  ├─ CatalogService：分页、限速、重试、去重和成功任务发布
  ├─ LocalDataStore：收藏、方案、标准化快照、变化和三天历史
  └─ IPC：Zod 校验、CSV 保存对话框、官方链接检查
```

渲染进程不能直接访问 Node.js、文件系统、Cookie 或原始 Token。

## 查询提交语义

查询任务先把所有页面归一化到临时集合。只有任务成功才发布新结果并写入标准化快照；失败或取消保留旧结果。

`coverageComplete` 仅在已加载页数覆盖平台计算出的远端总页数时为真。监控变化只比较两个 `coverageComplete` 快照，部分查询不会替换最近的完整基线。

## 收藏历史

每次成功查询后：

1. 使用主结果更新其中出现的收藏。
2. 对主结果未覆盖、上次库存大于零的收藏顺序执行一次精确名称搜索。
3. 只记录库存大于零的样本。
4. 按 30 分钟桶合并，售价和成本分别取最低值。
5. 对外只返回最近 3 天记录，后续快照会清理过期点。

收藏刷新不加入主查询结果，也不影响本地筛选统计。单项失败只记入刷新统计；429 会终止剩余刷新并触发冷却。

## 本地数据

`local-library-v1.json` 只保存标准化字段，不保存完整响应。每个查询范围最多保留最近快照，并额外保住最近一次完整基线；变化事件最多 500 条，查询范围最多 12 个。

## 商户写操作

只有 `connectGoods` 和 `disconnectGoods` 会修改商户商品。它们必须由用户在明确按钮和确认框中发起；收藏、方案、导出、监控和体检均不修改平台数据。
